# Music Industry Lap — Full stack journey demo (งานทดลองระยะถัดไป)

**Phase 1 ที่ผู้สร้างเลือกคือ [portal ลิงก์ไปยังแหล่งที่มีอยู่](../portal/README.md)**. โฟลเดอร์นี้เก็บงานทดลอง flow ตลาดครูสำหรับตัดสินใจในอนาคต ไม่ใช่บริการที่ต้องเปิดในขั้นแรก

แอปบนเครื่องสำหรับทดสอบเส้นทาง **ผู้เรียน → ครู → ผู้ดูแล** โดยมีหน้าเว็บ, API, การตรวจสิทธิ์ตาม persona, การตรวจข้อมูลฝั่งเซิร์ฟเวอร์ และข้อมูลที่ยังอยู่หลังรีสตาร์ต แตกต่างจาก `app-demo/` เดิมที่เก็บข้อมูลในเบราว์เซอร์เท่านั้น

## ทดลอง journey ให้ครบ

1. เลือก **ครูต้น** → “ลงบริการสอน” → กรอกเองหรือ “เติมตัวอย่างเพื่อทดลอง” → บันทึกร่าง → “ส่งตรวจรายการ”
2. เปลี่ยนเป็น **แพร** → “คิวตรวจรายการ” → อ่านข้อมูลและกดอนุมัติ หรือส่งกลับพร้อมเหตุผล
3. เปลี่ยนเป็น **มีน** → “ลองบทบาท” → หาครู หรือเข้าหน้า “หาครู” ทันที → เปิดรายการที่อนุมัติ → ส่งเป้าหมาย เวลา และงบ
4. เปลี่ยนเป็น **ครูต้น** → “คำขอเรียน” → ตอบรับ/ปฏิเสธ
5. กลับเป็น **มีน** → “คำขอของฉัน” เพื่อดูสถานะที่เปลี่ยนจากเซิร์ฟเวอร์

ข้อมูลเริ่มต้นมี 2 รายการอนุมัติและ 1 รายการรอตรวจ ทุกคนและบริการเป็น **ตัวอย่างสมมติ**

## สัญญาหน้าเว็บ ↔ API

| ขั้น | API | กฎสำคัญ |
|---|---|---|
| เลือก persona | `POST /api/demo/session` | สร้าง cookie session เพื่อทดสอบสิทธิ์ตามบทบาท |
| ครูสร้างร่าง | `POST /api/listings` | ตรวจฟิลด์ ช่วงราคา เวลา และชนิดวิชาฝั่งเซิร์ฟเวอร์; สถานะ `draft` |
| ครูส่งตรวจ | `POST /api/listings/:id/submit` | เจ้าของรายการเท่านั้น; `draft/rejected → pending` |
| ผู้ดูแลตรวจ | `POST /api/admin/listings/:id/review` | ผู้ดูแลเท่านั้น; `pending → approved/rejected` |
| ผู้เรียนค้น | `GET /api/listings` | คืนเฉพาะ `approved`; รองรับวิชา รูปแบบ และมีเครื่องให้ลอง |
| ผู้เรียนขอเรียน | `POST /api/requests` | ต้องเป็นรายการที่อนุมัติ; ตรวจเป้าหมาย/เวลา/งบและกันคำขอซ้ำที่ยังเปิดอยู่ |
| ครูตอบ | `POST /api/requests/:id/respond` | ครูเจ้าของบริการเท่านั้น; `pending → accepted/declined` |
| ดูงานของตน | `GET /api/my/listings`, `GET /api/my/requests` | จำกัดข้อมูลตามบทบาทและเจ้าของ |

ทุก mutation เขียนไฟล์ JSON แบบต่อคิวและสลับไฟล์หลังเขียนสำเร็จเพื่อไม่ให้คำขอพร้อมกันเขียนทับกันใน **เซิร์ฟเวอร์หนึ่ง process**; เหมาะสำหรับ pilot บนเครื่องเดียว ยังไม่ใช่ฐานข้อมูล production

| `POST /api/places/:id/reports` · `POST /api/places/suggest` | ผู้ใช้ทั่วไป/ผู้ให้บริการ | กันรายงาน/ข้อเสนอซ้ำ; ข้อเสนอต้องมีลิงก์ https (ไม่รับ Google Maps) หรือที่อยู่ |

ภาพต้นฉบับ 3 persona แรกสร้างด้วย built-in imagegen และบันทึกใน `public/assets/` (อีก 7 persona ใหม่ใช้อักษรย่อแทนภาพ):

- `persona-admin.png`: หญิงไทยวัยประมาณ 31 ผู้ประสานงานชุมชน ถือแฟ้มในพื้นที่ซ้อมดนตรี

ทุกภาพเป็นคนสมมติ ไม่ใช่โปรไฟล์ของครู/ผู้เรียนจริง และใช้โทนภาพ editorial อุ่น เขียวหม่น ให้เข้ากับ UI เดิม

## ขอบเขตก่อนใช้กับคนจริง

การเลือก persona ในหน้านี้ **ไม่ใช่ระบบล็อกอินจริง**: ผู้ใช้เครื่องเดียวกันเปลี่ยนเป็นผู้ดูแลได้เพื่อทดลอง flow เซิร์ฟเวอร์ยังตรวจสิทธิ์ของ session ตามบทบาท แต่ต้องแทนด้วยบัญชีจริงและการตรวจตัวตนก่อนเปิดสาธารณะ ยังไม่มีการจองเวลา ชำระเงิน ส่งข้อความ แจ้งเตือน หรือพิสูจน์ประสบการณ์ของครู ผู้เยาว์ต้องมี flow ผู้ปกครองแยกต่างหากก่อนใช้จริง

ข้อมูลที่กรอกใน pilot เก็บใน `data/store.json` บนเครื่องนี้ อย่ากรอกข้อมูลส่วนตัวจริงที่ไม่จำเป็น และอย่านำเซิร์ฟเวอร์นี้ออกสู่เครือข่ายสาธารณะ
