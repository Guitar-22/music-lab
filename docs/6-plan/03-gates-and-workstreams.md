# Gate และแผนงานคู่ขนาน

รวม "Gate plan" และ "แผนงานคู่ขนาน" ไว้ที่เดียว · Gate ระดับโครงการ (G0–G5) ด้านล่างครอบ Gate ของข้อมูลใน [database](../../database/README.md) (A ต้นทาง · D สถานที่ · B ฐานข้อมูล · C ความคลาดของ audit) ซึ่งเป็นการตรวจอัตโนมัติของ G1–G2

## ส่วนที่ 1 · Gate ระดับโครงการ

อัปเดต 26 กันยายน 2569 · Portal ระยะแรกเชื่อมผู้เรียนไปยังแหล่งภายนอก

| Gate | งาน | เงื่อนไขผ่าน | สถานะ |
|---|---|---|---|
| G0 กรอบข้อมูล | แยกสถาบัน หลักสูตร แบรนด์ สาขา คอร์สสาธารณะ แอป/เว็บ; กำหนด 6 โซน 50 เขต | ID และหน่วยนับไม่ปนกัน | ผ่านขั้นตั้งต้น |
| G1 รวบรวม | เก็บมหาวิทยาลัย โรงเรียน ร้านดนตรี อุปกรณ์ แอป/เว็บ และ candidate จาก Maps รายเขต | ทุกเขตและทุกหมวดคำค้นมีผลหรือระบุว่าไม่พบ; ทุกแถวมีที่มา | ยังไม่ผ่าน |

| G3 ตรวจดิจิทัล | เปิด URL เว็บ/App Store ตรวจไอคอน ภาพ ระบบรองรับ และราคา | ผ่านทีละรายการ; ภาพเสียมี fallback | ยังไม่ผ่าน |

### งานแบ่งตามสาย

- **Places research:** สำรวจเขตศูนย์กลางก่อน จากนั้นไล่รายโซน; เก็บโรงเรียน ร้านค้า สตูดิโอ และสถานที่แสดงแยกประเภท. ตัดผล sponsored นอกเขตและ deduplicate สาขา.
- **Curriculum research:** ตรวจหลักสูตรและรอบรับสมัครล่าสุดจากเว็บไซต์สถาบัน; แยกชื่อหลักสูตรจากหมวดวิชา.
- **Digital resource audit:** ตรวจแอป/เว็บและไอคอนบนหน้าเจ้าของหรือ App Store พร้อมบันทึกวันที่เปิดจริง.
- **UX/Dev:** ใช้ `27-persona-use-cases-handoff.md` เป็นสัญญางานฝั่งผู้ใช้; แสดง provenance และสถานะข้อมูล.
- **QA:** ตรวจยอดตามหน่วยนับและความสอดคล้องระหว่างฐานข้อมูล CSV กับหน้า Portal ทุก Gate.

### สถานะข้อมูลตั้งต้น

Portal มีแอป/เว็บ 35 รายการ, สถาบันอุดมศึกษา 25 แห่ง, โรงเรียน/คอร์ส 11 กลุ่มและ 38 จุดย่อยที่ระบุชื่อ. ตาราง `audit/bangkok-district-audit.csv` มี 50 เขต × 6 คำค้น = 300 ช่องตรวจ; ปทุมวันตรวจคำค้นทั่วไปครั้งแรกเท่านั้น อีก 5 คำค้นในเขตนั้นและ 49 เขตยังค้าง. ภาพสินค้า 21 รายการเป็น candidate ที่ยังต้องตรวจการใช้และการโหลด. ตัวเลขเหล่านี้เป็น **seed inventory** ไม่ใช่จำนวนรวมของตลาด.

### วิธีตรวจแต่ละเขต

1. เปิดคำค้นทั้ง 6 แบบใน `audit/bangkok-district-audit.csv` และเพิ่ม candidate โดยบันทึกชื่อ ที่อยู่ เขต ประเภท URL Maps และเวลาตรวจ.
2. แยกโฆษณา/ผลนอกเขต/ชื่อซ้ำ/กิจการที่ไม่สอน; ตรวจหน้าเจ้าของและพิน.
3. เก็บ `candidate → official_source_found → map_pin_checked → active_confirmed` หรือ `stale/outside_district/duplicate/not_a_school`.
4. เมื่อครบเขต จึงเลื่อนไปเขตถัดไป; บันทึกช่องที่ไม่พบผลด้วย เพื่อแยก “ค้นแล้วไม่พบ” จาก “ยังไม่ค้น”.

แหล่งแบ่งเขต: [ข้อมูล 6 กลุ่มเขตของ กทม.](https://apps.bangkok.go.th/info_gidsedbkk/m.info/sucgess/sucgess.html); รูปแบบ URL: [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started). แผนนี้ใช้กับงานสำรวจที่กำลังดำเนินในโฟลเดอร์เดียวกันโดยไม่แก้ไฟล์ collector หรือฐานข้อมูลของงานนั้น.


## ส่วนที่ 2 · สายงานคู่ขนาน

### จุดยืนระยะแรก

ทำ **Portal ฟรี** ที่ช่วยคนทุกระดับค้นหาสายดนตรี แหล่งเรียน เครื่องมือ และสถานที่ที่เหมาะกับตน แล้วพาไปยังหน้าเจ้าของข้อมูล. ฐานข้อมูลและการสำรวจสถานที่รายเขตเป็นงานหลักอีกสายหนึ่ง; งานในเอกสารนี้ทำคู่ขนานได้โดยไม่แก้ไฟล์ collector, curated place หรือ schema ระหว่างที่สายข้อมูลกำลังทำงาน.

### ขอบเขตไฟล์ เพื่อไม่ให้แก้ชนกัน

- สาย F เป็นเจ้าของ `database/sources/`, `database/lib/`, `database/schema.sql` และการนำเข้าข้อมูลสถานที่. การแก้ส่วนนี้ควรตรวจ Gate ฐานข้อมูลทุกครั้ง.
- สาย A–D เริ่มจากเอกสารแยกในโฟลเดอร์ `workstreams/` ก่อน. เมื่อต้องเปลี่ยน `portal/` ให้ทำจากรายการที่มีหลักฐานผ่าน Gate แล้ว และตรวจว่าหน้าเว็บเดิมยังทำงาน.
- สาย E อ่านผลจากทั้งสองฝั่งและสร้าง test/metrics spec แยก; ไม่เปลี่ยนความหมาย `verified` เอง.
- `platform/` เป็น demo ตลาดครูในอนาคต. ระยะแรกไม่เอาระบบลงงาน/จอง/จ่ายเงินมาเป็นเงื่อนไขเปิด Portal.

### ลำดับการบูรณาการ

1. **หลัง G0:** A, B, C, D เริ่มพร้อม F ได้เลย. C ใช้ข้อมูลจำลองและติดป้ายว่าเป็น prototype.
2. **เมื่อ A และ B ผ่าน:** UX ใส่เนื้อหาแนะแนวและทรัพยากรที่ตรวจแล้ว; QA ตรวจการนำทางและลิงก์.
3. **เมื่อ F ส่งเขตที่ผ่าน Gate:** UX รับเฉพาะรายการที่มี source/status; เริ่มจากปทุมวันและเขตแกนกลาง. ไม่รอให้ครบ 50 เขตเพื่อทดลองการใช้งาน แต่ต้องแสดง coverage จริง.
4. **ก่อนเปิดสาธารณะ:** D และ E ตรวจทุกหน้าที่อ้าง “ได้รับการยืนยัน” และทุกยอดรวม. เปิดให้ผู้ใช้รายงานข้อมูลผิด.

### ตัวชี้วัด Pilot

- **Coverage:** จำนวนรายการที่ผ่านการตรวจ / จำนวนรายการตั้งต้น แยกตามประเภทและเขต; ห้ามรวมแบรนด์กับสาขา.
- **Findability:** สัดส่วนผู้ทดลองที่หาแหล่งเรียนเหมาะกับเป้าหมายและพื้นที่ได้ภายในงานทดสอบ.
- **Source trust:** สัดส่วนผลค้นหาที่มีแหล่งต้นทางและวันที่ตรวจ; จำนวนรายงานลิงก์เสีย.
- **Handoff:** สัดส่วนผู้ใช้ที่เปิดแหล่งต้นทางหลังอ่านรายละเอียด และกลับมาปรับตัวเลือก.
- **Access gap:** เขต/สายงาน/ระดับที่ไม่มีรายการผ่านการตรวจ; บันทึกเป็นช่องว่างข้อมูล ไม่ตีความว่าไม่มีบริการจริง.

### จุดตัดสินใจหลัง Pilot

ใช้หลักฐานจากงานทดสอบและข้อมูล coverage เลือกว่าจะเพิ่มหมวด/เขตใดก่อน. โมเดลรายได้และตลาดครูอยู่หลังการพิสูจน์ว่า Portal ช่วยให้ผู้เรียนหาแหล่งที่เหมาะได้จริง ตามความตั้งใจที่จะให้ใช้ฟรีในช่วงแรก.
