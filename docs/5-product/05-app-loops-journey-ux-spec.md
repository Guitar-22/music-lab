# Loop ของแอป · Journey · UX/UI spec · Backlog งาน Dev

26 กันยายน 2026 · มาจาก [10 persona และ use case](../4-users/04-personas-and-use-cases.md) · ข้อมูลสถานที่จาก [database/](../../database/README.md) · ต่อยอด [platform/](../../platform/README.md)

## หลักการ

1. **ทุก loop ต้องปิดวงได้**: trigger → action → reward → investment (สิ่งที่ผู้ใช้ฝากไว้) → trigger ครั้งถัดไป ถ้าไม่มี investment ผู้ใช้จะไม่กลับมา
2. **ข้อมูลสถานที่มาจากฐานข้อมูลที่ผ่าน Gate** เท่านั้น; ข้อมูลที่ผู้ใช้สร้าง (รายงาน เคลม แผนซ้อม) เก็บแยกใน store ของ platform
3. **ทุก loop จบนอกแอปได้**: ปุ่มโทร/LINE/เว็บเจ้าของ/ลิงก์ Google Maps (เปิดให้ผู้ใช้ตรวจเอง — แอปไม่คัดลอกข้อมูลจาก Maps)
4. **ความสดของข้อมูลเห็นได้ทุกที่**: "ตรวจเมื่อ … · แหล่ง …"

## Journey ตัวอย่างข้าม loop

- **แม่ปุ๊ก (P2):** L2 แผนที่ → กรอง "โรงเรียน · รับเด็ก · ≤ 5 กม." → เปรียบเทียบ 2 แห่ง → ติดต่อ LINE → L9 อนุมัติคำขอคาบทดลอง → L8 รายงานว่าราคาเปลี่ยน
- **ฟ้า (P6):** L2 กรอง "ห้องซ้อม · เปิดหลัง 19:00 · ใกล้ BTS" → บันทึก → L5 โปรไฟล์วง → ยื่นเวทีของพี่โอ๊ต (P8)
- **เจ๊หน่อย (P7):** L7 เคลมร้าน → แก้เวลาเปิด (ขึ้นทันที ป้าย "เจ้าของแก้") → แก้บริการ "เช่ากีตาร์" (ฟิลด์เสี่ยง → คิวแพร) → L8 แพรอนุมัติ
- **ลุงชาญ (P4):** โหมดตัวใหญ่ → L2 "ดนตรีไทย · ใกล้บ้าน" → ปุ่ม "ส่งให้ LINE" → L10 ติดตามกิจกรรมกลุ่มระนาด

### หน้าจอหลักใหม่

1. **แผนที่ดนตรี (UC-03, 14, 21)** — แผนที่ SVG 50 เขตจากขอบเขต OSM; สีเขตตามจำนวนสถานที่; จุดสีตามชั้น ecosystem (เรียน/อุปกรณ์/สร้าง/แสดง/ฟัง/ธุรกิจ); แผงกรอง: ชั้น, ประเภท, เขต, คำค้น; รายการด้านข้างเรียงตามเขต; คลิกจุด/รายการ → การ์ดรายละเอียด
2. **การ์ดสถานที่ (UC-05, 19, 21)** — ชื่อ ประเภท ที่อยู่ เวลา โทร เว็บ/โซเชียล · ป้ายความสด + แหล่ง (OSM/เว็บเจ้าของ/เจ้าของยืนยัน) · ปุ่ม เปิด Google Maps / บันทึก / รายงานข้อมูลผิด / (ผู้ให้บริการ) เคลม
3. **รายงานข้อมูลผิด (UC-19)** — เลือกเหตุผล 1 ใน 5 (ปิดแล้ว, ย้าย, เวลา/เบอร์ผิด, ไม่เกี่ยวกับดนตรี, อื่นๆ) + ข้อความสั้น; ผู้ใช้เห็นสถานะในที่บันทึก
4. **คิวรายงาน (UC-20)** — เรียงตามความเสี่ยง: ปิดแล้ว/ไม่เกี่ยว > ฟิลด์เสี่ยงจากเจ้าของ > อื่นๆ; ปุ่ม ยอมรับ/ปฏิเสธพร้อมเหตุผล
5. **สถานที่ของฉัน (UC-16, 18)** — เคลม (ส่งคำขอ + หลักฐาน) → เมื่ออนุมัติ แก้ฟิลด์ปลอดภัยทันที, ฟิลด์เสี่ยงเข้าคิว; เห็นจำนวนการบันทึก/รายงาน
6. **แผนซ้อม (UC-06, 07)** — เป้าหมาย + นาที/สัปดาห์ → แผน 8 สัปดาห์; บันทึกการซ้อม (นาที, สิ่งที่ฝึก, ความรู้สึก 1–3); แถบความคืบหน้าสัปดาห์นี้
7. **อุปกรณ์ (UC-09, 10)** — 3 คำถาม → คำแนะนำ ยืม/เช่า/มือสอง/ใหม่ พร้อมเหตุผลและช่วงงบ + ร้าน/ร้านซ่อมจากแผนที่
8. **ความคืบหน้ารายเขต** — ตาราง 50 เขต × wave × จำนวนสถานที่ × สถานะการตรวจ (จาก gate_runs และ district_progress)

### UI rules

- ตัวอักษรเริ่ม 16px; ปุ่ม **โหมดตัวใหญ่** (P4) ขยายเป็น 20px และซ่อนข้อความรอง
- ทุกการ์ดสถานที่มีป้ายความสด; ข้อมูลไม่มี = "ยังไม่มีข้อมูล" ไม่ซ่อนช่อง
- สีชั้น ecosystem ใช้ร่วมทั้งแผนที่ รายการ และป้าย; ไม่ใช้สีเป็นตัวบอกเพียงอย่างเดียว (มีข้อความประเภทกำกับ)
- ไม่มี auto-play, ไม่มีโฆษณาในหน้าแรก (ข้อขัดแย้ง P1 ↔ P7)

## สัญญา API ใหม่

| API | บทบาท | กฎ |
|---|---|---|
| `GET /api/districts` | ทุกคน | 50 เขต: wave, จำนวนสถานที่ตามชั้น, path SVG |
| `GET /api/places?district=&layer=&kind=&q=` | ทุกคน | เฉพาะรายการที่ไม่ excluded; ใส่ overrides ที่อนุมัติแล้วของเจ้าของ |
| `GET /api/places/:id` | ทุกคน | รายละเอียด + แหล่ง + ความสด + ลิงก์ Maps |
| `POST /api/places/:id/reports` | ผู้ใช้ที่ไม่ใช่ admin | เหตุผลต้องอยู่ในรายการ; กันรายงานซ้ำที่ยังเปิดจากคนเดิม |
| `GET /api/admin/reports` · `POST /api/admin/reports/:id/resolve` | admin | เรียงตามความเสี่ยง; ปฏิเสธต้องมีเหตุผล |
| `POST /api/places/:id/claim` | teacher/shop/venue | หนึ่งเจ้าของต่อสถานที่; เข้าคิว admin |
| `POST /api/places/:id/edit` | เจ้าของที่อนุมัติแล้ว | ฟิลด์ปลอดภัย (hours, phone, website, social, offer) ขึ้นทันที; ฟิลด์เสี่ยง (name, kind, address, ages, price) เข้าคิว |
| `GET/POST /api/me/saved` | ทุกคนที่ไม่ใช่ admin | toggle บันทึก |
| `GET/POST /api/me/plan` · `POST /api/me/practice` | กลุ่มผู้เรียน | แผน 8 สัปดาห์ + บันทึกซ้อม (นาที 5–240) |
